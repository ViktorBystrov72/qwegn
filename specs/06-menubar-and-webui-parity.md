# 06 — Menu Bar (`@Observable`) & WebUI Telemetry Parity

> Normative specification for `QWMenuBarUI` (`Sources/Apps/QWMenuBar/`), `Qwegn.app` bundling, `QWSettingsCoherence`, and `/ui` parity.

## 1. Observation Architecture (`@Observable`)
- `TelemetryObservable` (`Sources/Apps/QWMenuBar/TelemetryObservable.swift`) is `@MainActor @Observable` (no `ObservableObject` or `@Published`), importing `Observation`.
- Internal timers, `Task` handles, `Process` handles, and stale-fetch tokens (`pollTimer`, `loggerSubscriptionId`, `serverProcess`, `lastKnownServerPid`, `nextLogSequence`, `isPopoverVisible`, `isLogWindowVisible`, `dashboardStreamTask`, `logStreamTask`, `lastDashboardStreamAt`, `dashboardGeneration`, `engineInfoGeneration`, `lastErrorPhase`) are annotated `@ObservationIgnored` so non-UI housekeeping never triggers SwiftUI invalidation.
- `init(startServices: Bool = true, enableAutoLifecycle: Bool = true, initialSettings: QWServerSettings? = nil)` supports hermetic unit testing (`startServices: false` / `enableAutoLifecycle: false`) while preserving zero-argument production startup (`TelemetryObservable()`).
- Views accept plain `var telemetry: TelemetryObservable` (`CupertinoTelemetryView`, `SettingsView`, `LogViewerWindow`) or `@Bindable var telemetry: TelemetryObservable` where `$telemetry.*` bindings are required (`SettingsMenuBarAppearanceView`).
- `QWMenuBarApp` updates `NSStatusItem` through `withObservationTracking` (`observeStatusItem()`), re-evaluating only when properties read by `menuBarStatusState` or `menuBarStatusTitle` mutate.

## 2. Single-Source Telemetry & Honesty Invariants
Both `Qwegn.app` and `QWServer` (`/ui` backed by `Sources/Apps/QWServer/Resources/{controlbar.html,logo.svg,css/{base,panels,chat}.css},js/{state,dashboard,markdown,chat-presets,chat,actions}.js}`) render from `QWDashboardViewModel` (`QWDashboardBuilder`):
- **Catalogue lockstep:** Every card ID read in `QWMenuBar` (`TelemetryCards.swift`) belongs to `MenuBarCardCatalogue.ids`; `/ui` cards belong to `QWDashboardBuilder.cardSpecs`.
- **Zero fabricated state & offline modular assets:** Missing metrics render `—` with `card.reason` tooltips; UI code must never read `engineInfo` / `settings.modelName` for active model titles or synthesize `"Idle"` / `"Stopped"` fallbacks when disconnected (`MenuBarRendererParityTests`, `DashboardRendererParityTests`, `QWTelemetryHonestyTests`). All `/ui` CSS/JS assets are copied via `Package.swift` `.copy(...)` and served strictly offline (`Cache-Control: no-cache`, zero `https://` CDN links), Smoke Probe Markdown output (`js/markdown.js`) renders offline with strict HTML escaping, URL scheme filtering, code-block copy buttons, and `Raw` / `Rendered` toggle, and the dedicated Chat workspace (`?tab=chat`, `js/{chat-presets,chat}.js`) persists multi-turn sessions/presets strictly in browser `localStorage`, streams SSE via `/v1/chat/completions`, applies preset harness profiles and `.qwcache` `QWMemoryPack` workspace auto-discovery/inspection/live SSE indexing/mounting (`/v1/memory/inspect`, `/v1/memory/index`, `/v1/memory/mount`, `/v1/memory/unmount`, `#modal-memory-pack` covering `missing`, `wrong_model` with `Switch & Mount`, `stale` with `Update & Mount` / `Mount Existing with Live Delta`, and `ready`), exposes per-session knobs/tools/vision attachments, emits standardized Chat-to-Engine request metadata (`X-Request-ID`, `X-Session-ID`, `session_id`, `cache_prompt`, `prompt_cache_key`/`cache_salt`, `store`, `metadata.{workspace_path,use_memory_pack,exact_speculation,preset_id}`, bridged uniformly across `/v1/chat/completions` and `/v1/messages`, `QWEngineDriver` + `FNGPUEngine` prefix caches, and `QWRequestRecord.config`), and syncs default `systemPrompt` edits back to `/v1/settings`.
- **Cross-phase sparkline continuity without synthetic values:** `QWEngineTelemetryRegistry` preserves `nil` on unmeasured slots (`1 Hz` decode-only slots stay `nil` in `prefillRateSeries`), while `QWSparklineGeometry` and `/ui` `updateSparkline` bridge `nil` slots only when the companion phase holds a positive sample on the same timestamp, keeping `Prefill`/`Decode` lines continuous across turns and still breaking on true dual-nil gaps.
- **Layout bounds & running-text marquee:** `CupertinoTelemetryView` locks its root popover frame to `440pt` (`420pt` inner content width with `10pt` concentric outer padding and `8pt` inter-card spacing, `.clipped()`), while `headerSection` and `loadedWeightsCard` action stacks hold `.layoutPriority(1)`. Oversized resident model names (`lifecycle.model`) and wide quantization pills scroll smoothly inside fixed single-line slots via `MarqueeText` (`Sources/Apps/QWMenuBar/MarqueeText.swift`, `1.4s` initial hold, `28 pt/s` seamless loop, `@Environment(\.accessibilityReduceMotion)` static fallback) without widening the popover or clipping card edges. In `/ui`, `#hero-model-title` mirrors this with `.hero-model-marquee` + `@keyframes qwg-hero-marquee` (`prefers-reduced-motion` safe) and `dataset.sig` identity preservation so `1 Hz` SSE refreshes do not reset scrolling.
- **Lifecycle boundary & restart coherence:** `QWSettingsCoherence` classifies every setting into `.live` vs `.serverRestart`. Server header actions use `restartServerProcess()` / `toggleDaemon()`; model actions stay inside `RESIDENT MODEL`.

## 3. Co-Bundled Binary & Packaging
- `Package.swift` splits reusable views/state into `QWMenuBarUI` (`L8.5`, unit-tested by `QWMenuBarTests`) and keeps `qwg-menu` (`L9.0`, `Sources/Apps/QWMenuBarEntry`) as the thin `@main` executable.
- `Scripts/build_app.sh` embeds and code-signs release `qwg` inside `Qwegn.app/Contents/MacOS/qwg` so `TelemetryObservable` launches the matching signed engine sibling binary regardless of working directory.
